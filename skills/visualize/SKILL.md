# 可视化（Visualize）

一张图只有在展示文字表达不了的东西时才有资格存在——形状、结构、方向、关系、几何。本技能产出**一张**这样的图，保证它是**正确的**（制作者渲染它并在返回前亲眼看它），并把它放进课程里，使它在 Obsidian 的 `md-log` 文件中内联渲染。

你是**创意总监**。你决定确切的想法，并把它提炼到最少的承载元素。一个**制作者子代理**负责编写、渲染、目视校验和保存，然后返回一个文件名。你把这个文件名嵌入你的回复。

## 何时可视化（以及何时不）

这套教学系统在学习者脑中构建**依赖图**——公理在根部，派生事实挂在它们下面。当一个图示能让那种结构（或一种几何）可见时，它就很有力。在以下情况去用它：

- 这个想法是一种**结构或关系**：依赖关系、一个有部件和箭头的系统、一个流程/流水线、一连串交换、一个状态机、一棵树/层级、一个对比、一种包含关系（里面是什么 vs 外面是什么）。
- 这个想法是**空间或几何**的：坐标几何、数轴、向量、函数形状、物理布局。

当散文或一个方程已经能承载它时，不要可视化。一张只是把旁边那句话复述一遍的装饰性图示只会增加噪音和出错的可能。拿不准时，就不要画——缺一张图比一张错误的图更便宜。

## 选择制作者

两个制作者，从 `.pi/agents/` 中发现：

- **`mermaid-maker`** —— 结构/关系图示：依赖图、流程图、序列/状态/ER/类图、树、思维导图、时间线。这是默认项，也直接契合依赖图的教学法。
- **`svg-maker`** —— Mermaid 无法布局的空间/几何图示：精确坐标、几何图形、数轴、向量、函数图像、自定义形状。

经验法则：如果是*节点和边 / 关系*，用 mermaid-maker。如果是*位置和形状 / 几何*，用 svg-maker。

## 给制作者下达好的简报：一个想法，最少的元素

最常见的失败是**塞太多**——每多一个标签都会让图更难读**也**更难布局正确。在写简报之前，先精简到能承载这个想法的最少元素，并对每一个问：*"如果我删掉它，这个想法还清楚吗？"* 如果还清楚，就删掉它。

给制作者概念**以及**你想要的具体元素——不要给一个模糊的主题，也不要给一长串清单。

- 差："画一张关于 TCP 如何工作的图"
- 好："graph TD：顶部一个节点 'packet'；箭头向下到 'ordering' 和 'retransmit on loss'；两条箭头都向下汇入 'reliable stream'。不要标题。要展示可靠性是从数据包**构建**出来的，而不是与数据包并列的。"

保持想法完整，但信任制作者去构图；如果你的简报列了超过 ~5–7 个元素，先砍。

## 调用

用 `subagent` 工具派发制作者：

```
subagent(agent="mermaid-maker", task="<你的最小、具体的简报>")
```
```
subagent(agent="svg-maker", task="<你的最小、具体的简报>")
```

制作者拥有它自己专用的工具（`write_*`/`edit_*`/`render_*`）——它编写源码，渲染成 PNG，**亲眼看 PNG 并迭代，直到正确且干净**，用一个唯一文件名把它发布进 vault，并返回：

```
RESULT:
filename: viz-<slug>-<timestamp>.png
path: <cwd>/viz/viz-<slug>-<timestamp>.png
```

如果它返回 `RESULT: NONE`，说明它无法就这个简报做出正确的图——简化或重新思考，或决定这张图不值得。绝不要自己手写或伪造图示；正确性依赖于制作者的"渲染-检查"循环。

## 把它嵌入课程

把嵌入直接放进你的教学回复，用 Obsidian 的 wikilink 嵌入，带上返回的**文件名**（不是完整路径）和一个显示宽度：

```
![[viz-<slug>-<timestamp>.png|500]]
```

就这样。`md-log` 扩展会把你的回复文本逐字镜像到关联的 `.md` 里，而 Obsidian 在 vault 里按文件名解析嵌入（制作者保存到项目的 `viz` 文件夹，它在 vault 内部）——于是它自动内联渲染在课程里。宽度 `|500` 是个不错的默认值；密集的图用大一点。先用一句话引入这个图示，然后让它自己承载想法——不要再用散文把每个元素复述一遍。

## 为什么这样可靠

- 制作者从不返回一张它没有**看过**的图，所以"渲染没问题但说的是错的"会在到达学习者之前被抓住。
- PNG 嵌入意味着**制作者校验过的东西与学习者看到的东西像素级一致**——没有重新渲染的漂移。
- 唯一文件名让 Obsidian 按文件名的嵌入解析没有歧义。

> 制作者通过项目的 `visual-tools` 扩展来渲染（Mermaid 经由打包的 `@mermaid-js/mermaid-cli` + 已安装的 Chrome；SVG 经由 `rsvg-convert`，回退 ImageMagick）。你自己不渲染任何东西——你只下达简报并嵌入它返回的文件名。
